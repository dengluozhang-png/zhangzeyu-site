## 一句话版

> 当 Agent 开始自动执行副作用，治理不再是"prompt 工程"，而是 **双轨工程**。

## 双轨

| 维度 | 内部合规 | 外部合规 |
|---|---|---|
| 责任主体 | Agent 团队 / 工程 | 公司 / 法务 / 备案 |
| 表达语言 | 自然语言宪法 + 代码 | 监管条款 + 文档 |
| 触发时机 | 每次决策前 | 上线前 / 重大变更前 |
| 可回滚性 | 立即停（kill switch） | 按监管要求 |
| 证据 | 日志、可观测链 | 备案文档、审计报告 |

## 为什么分开

- **内部合规跟模型强绑定**：宪法条款改了，旧 prompt 就要重训。
- **外部合规跟监管强绑定**：条款 5 年才动一次。
- 混在一起，会出现 "**我们修了 prompt 但备案没更新**" 这种典型落地事故。

## 设计原则

1. **内部合规是行为约束**：你能改，要快。
2. **外部合规是事实陈述**：你不能乱动。
3. **两者用 switch 隔离**：内部开关指向"宪法版本号"，外部指向"备案版本号"。
4. **每次外部合规材料变动，要去对照内部合规**：这是容易漏掉的一环。

## 还没想清楚的

- 当 Agent 多层嵌套时，到底是谁的合规？
- 当 Agent 是用户自己部署（自部署）时，"合规"的责任是不是退回到用户？
